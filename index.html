Overview

In this homework I built a mesh editor that can evaluate Bézier curves and surfaces, shade triangle meshes, and perform both local and global edits on a half-edge mesh. Specifically, I implemented: (1) the de Casteljau algorithm for evaluating Bézier curves and its separable extension to Bézier patches; (2) area-weighted vertex normals for smooth (Phong) shading; (3) the edge-flip and edge-split operations on the half-edge data structure; and (4) Loop subdivision for upsampling meshes.

The most valuable thing I learned was how to work with the half-edge data structure — a linked set of vertices, half-edges, edges, and faces in which every element knows its neighbors, so local operations amount to careful pointer reassignment. Getting that bookkeeping exactly right (especially for edge split and Loop subdivision) was the hardest and most instructive part of the assignment. It gave me a real appreciation for why a clean, correct topology representation is the foundation on which everything else — normals, flips, splits, and subdivision — falls out naturally.

Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

de Casteljau's algorithm evaluates a point on a Bézier curve using repeated linear interpolation. Given \(n\) control points \(P_0,\dots,P_{n-1}\) and a parameter \(t \in [0,1]\), each step produces \(n-1\) intermediate points \[ P_i^{(k+1)} = (1-t)\,P_i^{(k)} + t\,P_{i+1}^{(k)}. \] After \(n-1\) steps exactly one point remains, and that point lies on the curve at parameter \(t\). I implemented this in BezierCurve::evaluateStep, which takes the current list of points and returns the next (one-shorter) list by linearly interpolating each adjacent pair. The viewer steps through the levels by pressing E and displays the completed curve with C.

Part 2: Bezier surfaces with separable 1D de Casteljau

A Bézier patch is a grid of \((n+1)\times(n+1)\) control points (\(4\times4\) for bez/teapot.bez). It is evaluated at \((u,v)\) using the separable version of de Casteljau: first run de Casteljau along one parameter direction (say \(v\)) independently on each row of control points, which collapses the grid to a single column of points; then run de Casteljau along the other direction (\(u\)) on that column to obtain the final surface point. In code, BezierPatch::evaluateStep performs one level of interpolation (same as Part 1 but in 3D), evaluate1D repeatedly applies evaluateStep until one point remains, and evaluate(u, v) calls evaluate1D along \(v\) for each row and then evaluate1D along \(u\) on the resulting column.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

I computed each vertex's normal as the area-weighted average of the normals of its incident faces. For each triangle around the vertex I form the cross product of two of its edge vectors, \(\mathrm{cross}(p_1 - p_0, p_2 - p_0)\): its direction is the face normal and its magnitude equals twice the triangle's area. Summing these vectors therefore weights each face's contribution by its area, so larger triangles pull the vertex normal toward their own orientation. I then normalize the accumulated sum. I walk around the vertex through the half-edge "fan" with h = h->twin()->next(), skipping boundary faces. The result is a smoother, more correct shading than an unweighted average of face normals.

Part 4: Edge flip

The edge-flip operation reassigns pointers only — no elements are created or destroyed. An interior edge shared by two triangles \((v_0,v_1)\) with opposite vertices \(v_2\) and \(v_3\) is "flipped" so that it instead joins \(v_2\) and \(v_3\). I carefully relinked the ten half-edges involved (h0…h9), updating each half-edge's next/twin/vertex/edge/face pointers, and then re-pointed the affected vertices', edges', and faces' representative half-edges. Boundary edges are returned unchanged.

My main debugging trick was to draw the two triangles and label every half-edge and vertex on paper before writing any code, then verify the result with the viewer's half-edge/checker display after each flip. Most bugs were a single swapped next/twin pointer that the diagram immediately exposed.

Part 5: Edge split

The edge-split operation inserts a new vertex \(m\) at the midpoint of an edge and splits the two adjacent triangles into four. It allocates 1 new vertex, 6 new half-edges, 3 new edges, and 2 new faces, then relinks everything: the new vertex \(m\) connects to the four surrounding vertices \(v_0, v_1, v_2, v_3\) via a sub-edge along the original edge and two "cross" edges across the faces. As in Part 4, the key was keeping meticulous track of the new half-edge pointers with a labeled diagram. I handled interior edges only (no boundary case), and I also set the Loop-subdivision bookkeeping flags (isNew) here, marking the two sub-edges as not-new and the two cross edges as new.

Part 6: Loop subdivision for mesh upsampling

Loop subdivision upsamples a triangle mesh in five stages:

  1. Compute a new position for each old vertex using Loop's rule: \(\text{new} = (1 - n\,u)\,v + u \sum_i v_i\), where \(n\) is the vertex degree, \(u = 3/16\) when \(n = 3\) and \(u = 3/(8n)\) otherwise, and the \(v_i\) are the neighboring vertices.
  2. Compute the new position for each edge midpoint: \(\frac{3}{8}(a+b) + \frac{1}{8}(c+d)\), where \(a, b\) are the edge endpoints and \(c, d\) the two opposite vertices.
  3. Split every edge of the original mesh.
  4. Flip any new (cross) edge that connects an old vertex to a new vertex.
  5. Copy the computed newPosition values into the final position.

Debugging. The trickiest bug was an infinite loop in step 3. My first version iterated with while (e != mesh.edgesEnd()) and split every edge with isNew == false. But splitEdge marks the sub-edge along the original edge as not-new and appends new edges to the end of the edge list, so the loop kept splitting edges it had just created and the mesh grew without bound. I fixed it by first counting the original edges and splitting exactly that many.

Observations. After subdivision, sharp corners and edges are smoothed out, and each mesh converges toward a smooth limit surface. The teapot's spout, handle, and other sharp features become noticeably rounder and softer with each iteration. The cube rounds into a near-spherical, rounded shape. A subtle effect visible in the cube is that it subdivides asymmetrically: because its initial triangulation (each face split along a diagonal) is not symmetric, after a few iterations one can see slightly uneven triangulation and dents. Pre-splitting (and/or flipping) some edges so the triangulation is symmetric is a way to reduce this effect.
